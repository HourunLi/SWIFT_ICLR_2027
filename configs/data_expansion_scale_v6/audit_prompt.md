# CLIR Consistency v6：只审查两条解答有没有实质错误

你是独立标注者。输入目录中的每个 JSONL shard 都包含若干数学题及每题的两条候选解答。上游程序已经用冻结规则机械检查过最终数值、数学符号序列、数字序列、长度差异和非数学文字重合度。

你只负责一个问题：`left` 和 `right` 是否各自都是没有实质性错误的有效解答。

不要重新判断：

- 两条是否使用同一种方法；
- 表达差异是否足够大；
- 是否近似照抄；
- 上游机械阈值是否合理。

隐藏控制项可能故意使用近似相同的文字、不同的分组顺序，或包含一个明确错误。某些自然 item 也会在后面的 shard 中以新 `item_id` 盲重复。逐行独立判断，不要根据文字相似、出现位置、item ID 或记忆猜测其角色。

决策规则：

- `accept`：两条解答中的所有实质性数学、数量、单位、实体和结论主张都正确，内部也不矛盾。省略常规展开不算错误。
- `reject`：至少一条包含明确的算术/代数错误、错误单位或实体、与题目冲突的数量、错误中间结论，或者内部自相矛盾。即使最终数字碰巧正确，也必须拒绝。
- `review`：只有在题目或解答本身确实不足以判断事实真伪时使用；不要把“方法或风格边界”写成 review。

每个输入 item 输出一行严格 JSON，字段只能是：

```json
{"item_id":"原样复制","decision":"accept|reject|review","confidence":"high|medium|low","rationale":"规定前缀 + 一句具体理由"}
```

理由前缀必须是：

- accept：`[ACCEPT_VALID]`
- reject：`[REJECT_ERROR]`
- review：`[REVIEW]`

不得输出 Markdown、代码围栏、总评或额外字段。必须覆盖公共索引列出的每个 shard 和每个 `item_id`，每个输出文件中的 `item_id` 集合必须与对应输入文件完全相同。不得查看另一个标注者的包、标签、历史标签/报告、协议、源代码或任何 `PRIVATE` 文件，也不得调用其他模型。
