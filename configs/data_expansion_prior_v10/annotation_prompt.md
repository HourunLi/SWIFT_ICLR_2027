# CLIR Prior v10：按同一套回溯算法标 Key / Complete

你只标当前公开 JSONL。不要查看任何 `PRIVATE_*` 文件、另一位模型的输出、CLIR checker、参考答案或历史标签。每行给出一道题、一条候选推理，以及已经固定编号的 `material_claim` unit。

本轮不允许自由选择“详细版”或“最短版”。所有行都必须按下面同一套算法标：

- `Key` 永远是一个锚点 unit：错误主线取最早致命错误；没有致命错误时取最晚一个首次完成候选答案的非包装 unit。
- `Complete` 是从候选最终实质结论向前回溯得到的实际推理链。它比 Key 宽，但不是全部 unit，也不是你重新解题后的最短证明。

## 1. 先判断能不能标

- 只有答案、拒答或没有可审计推理：`eligibility="no_auditable_reasoning"`。
- unit 边界把关键主张混在一起，按现有 unit 无法稳定判断：`eligibility="insufficient_unitization"`。
- 其余使用 `eligibility="usable"`。
- 不可用行的 Key/Complete 都必须是空数组；usable 行的 Key 必须恰好一个 index，Complete 必须非空。

## 2. Key：强制只选一个

先在心里检查候选实际用于最终结论的主线是否有致命错误，不需要输出 path status。

1. 如果主线有错误、无根据的假设、漏掉必要运算、单位/对象混淆或题目所求量理解错误：Key 选这条实际主线上最早出现的致命错误 unit。
2. 后面的错误结果只是前面错误的后果时，绝不能把后果选成 Key。
3. 如果有多个互不依赖的致命错误，选 unit index 最小的那个。
4. 如果主线没有致命错误：Key 选最晚一个“首次把候选所声称答案真正完成”的非包装 unit。若前面已算出两个根、最后一步依据“首次/最大/正数”等要求作选择，Key 是选择步骤。
5. `所以答案是……`、单独的 `\boxed{...}` 或纯同义复述不是 Key，除非这一行第一次引入了影响答案含义的错误，例如把“新速度 75 mph”误说成“快 75 mph”。

## 3. Complete：从最终结论向前做一次回溯

先找到最后一个真正参与推理的答案/选择 unit（排除纯包装），把它放入 Complete。然后从后向前扫描：

- 某 unit 产生了已经入选的后续 unit 实际使用的新中间量、关系、约束或分支选择，就纳入。
- 候选把一次计算拆成“代入后的算式”和“算出的结果”两个 unit 时，两者都纳入。例如 `260-195` 与下一行 `=65` 都保留。
- 如果一个 unit 已经完整写出“输入 + 运算 + 结果”，后面只重复结果的 unit 不纳入。
- 错误算式及沿错误结果继续计算的步骤仍属于候选实际主线，要纳入；不要偷偷改成正确解法。
- 题面中本来就给出的数字/事实，如果只是原样复述，且后面的入选算式已经写出它，不纳入。
- 不纳入标题、计划话术、只写通用公式但未代入、未被最终结论使用的旁枝、验算性重复、重复等式、同义复述和 final wrapper。
- 不能把较早推导出的中间量当成“已知”而直接删掉；也不能用你自己的更短公式替换候选实际做过的多步计算。

最后检查：`Key ⊆ Complete`，索引升序、无重复，并且只选择输入中 `kind="material_claim"` 的 unit。

## 4. 三个定标例子

### 例 1：拆开的计算要保留两行

- unit 0：`先列式 3×4`
- unit 1：`算得 12`
- unit 2：`再列式 12+2`
- unit 3：`算得 14`
- unit 4：`所以答案是14`

没有错误。应标 `Key=[3]`、`Complete=[0,1,2,3]`。unit 4 只是包装。

### 例 2：Key 必须是最早致命错误

- unit 0：`7+5=13`
- unit 1：`13×2=26`
- unit 2：`所以答案是26`

应标 `Key=[0]`、`Complete=[0,1]`。unit 1 虽直接给出结果，但只是沿用 unit 0 的错误，不能选成 Key。

### 例 3：复述题面不是 Complete

题目已给“上午卖 9 支、下午卖 6 支、退回 2 支”。

- unit 0：`9+6=15`
- unit 1：`题目说退回2支`
- unit 2：`15-2=13`
- unit 3：`答案13`

应标 `Key=[2]`、`Complete=[0,2]`。unit 1 是题面复述，unit 2 已直接写出数字 2。

## 5. 输出格式

每个输入行恰好输出一个单行 JSON，顺序可以跟输入一致。不要 Markdown、代码围栏、解释段落、额外字段或漏行：

```json
{"item_id":"原样复制","eligibility":"usable","key_unit_indices":[3],"complete_unit_indices":[0,1,2,3],"confidence":"high","rationale":"unit 3 首次完成答案；0/1 和 2/3 是候选实际使用的两段拆开计算"}
```

不可用行：

```json
{"item_id":"原样复制","eligibility":"no_auditable_reasoning","key_unit_indices":[],"complete_unit_indices":[],"confidence":"high","rationale":"只有答案，没有可审计推理"}
```

`confidence` 只能是 `high|medium|low`。`low` 只用于按上述算法仍确实无法稳定判断的行，不要把普通难题一律标 low。
