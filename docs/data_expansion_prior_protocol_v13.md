# Prior v13：机械拆主链的小烟测

v12 已经终止，原因不是可用样本数量不足，而是 Complete（“候选答案实际依赖的完整主链”）在重复标注和双模型之间不够稳定。单纯把被切碎的 unit 合并成 block，几乎没有改善；主要分歧来自“这句话到底属于主线，还是题面复述、通用公式、重复结果或没用到的旁枝”。

v13 只试一次尽量简单的新办法：

1. 程序安全合并同一计算被切开的碎片，但保留原始 unit index，训练轴不变。
2. 程序给每个 block 一个非强制角色提示。
3. 程序为每个推理步骤最多提出两个可能的直接父步骤。
4. AI 不再自由输出整个 Complete 集，只审核角色、局部依赖、最终步骤和 singleton Key。
5. 程序从最终步骤沿保留的依赖边向前回溯，机械生成 Complete。

## 新数据，不救 v12

烟测从 v12 已冻结但从未送标的 16,000 条 rollout 中抽 48 条 train-side 新轨迹，并排除 v12 800 条 proposal 的全部 query 与模板 cluster。48 条覆盖 GSM8K/MATH、数值匹配/不匹配、中等/长链八个格子，每格 6 条；同 query 和同 cluster 只取一条。

每位标注者看到 4 个 shard，每个 shard 为 12 条自然样本、2 条隐藏控制题、4 条跨 shard 自重复，共 18 条。A/B 分别为用户报告的 GPT-5.6-sol xhigh 与 Claude Opus 5 high，独立互盲、无人工复核、不裁决。

## 预冻结结论规则

只有全部门槛通过，才允许另立 v14 扩量协议。v13 自身的 48 条烟测标签不进训练。若 v13 失败，就停止继续改提示词，不做事后救援；届时再单独讨论是否把 v12 中严格共识的可用子集命名为“事后探索版 Silver”来做一次训练。这个探索版必须另立版本，并明确不能推翻 v12 的终局失败结论。

这里的通过只代表“双 AI 对这套局部审核定义足够稳定，可以扩量”，不代表标签等同人工、不代表 Prior 已经可学，更不代表 gate 或 Best-of-N 会提高。
