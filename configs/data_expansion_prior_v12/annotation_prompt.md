# CLIR Prior v12：先逐单元验算，再标 Key / Complete

你只标当前公开 JSONL。不要查看任何 `PRIVATE_*` 文件、另一位模型的输入或输出、CLIR checker、参考答案或历史标签。每行给出一道题、一条候选推理，以及固定编号的 `material_claim` unit。

本轮严格沿用 v11 的 Key/Complete 定义。必须先独立逐单元验算，再选择 Key 和 Complete。不要因为后续推理写得流畅或内部自洽，就默认更早的计算正确。

## 0. 强制先做逐单元验算

在输出任何标签前，按 unit index 从小到大，结合题目逐项检查所有 `material_claim`：

1. 重新计算每个算术或代数等式，不要照抄候选给出的结果；
2. 检查单位、换算、人物/物体、数量关系和题目实际所求量；
3. 判断后一步是在独立犯错，还是仅仅沿用了更早的错误结果；
4. 在心里记住实际主线上的第一个致命错误 unit；不要增加新的输出字段。

如果某行有错误，`rationale` 必须明确写出 Key 为什么错，例如“6×8 应为 48，不是 46”，不能只写“这里是最早错误”。如果验算后没有错误，rationale 说明哪个 unit 首次完成候选答案。

## 1. 先判断能不能标

- 只有答案、拒答或没有可审计推理：`eligibility="no_auditable_reasoning"`。
- unit 边界把关键主张混在一起，按现有 unit 无法稳定判断：`eligibility="insufficient_unitization"`。
- 其余使用 `eligibility="usable"`。
- 不可用行的 Key/Complete 都必须是空数组；usable 行的 Key 必须恰好一个 index，Complete 必须非空。

## 2. Key：强制只选一个

1. 如果实际最终主线有错误、无根据假设、漏掉必要运算、单位/对象混淆或所求量理解错误：Key 是逐单元验算发现的最早致命错误 unit。
2. 后面的错误结果只是前面错误的后果时，绝不能把后果选成 Key。
3. 如果有多个互不依赖的致命错误，选择 unit index 最小的一个。
4. 如果主线没有致命错误：Key 是最晚一个“首次把候选所声称答案真正完成”的非包装 unit。若最后还要依据“正数、最大、首次”等条件选答案，Key 是该选择步骤。
5. `所以答案是……`、单独的 `\boxed{...}` 或纯同义复述不是 Key，除非这一行第一次引入影响答案含义的错误，例如把“新速度 75 mph”误说成“快 75 mph”。

## 3. Complete：从最终结论向前回溯

先找到最后一个真正参与推理的答案/选择 unit（排除纯包装），把它放入 Complete，再从后向前扫描：

- 某 unit 产生了已入选后续 unit 实际使用的新中间量、关系、约束或分支选择，就纳入。
- 一次计算拆成“代入后的算式”和“算出的结果”两个 unit 时，两者都纳入。例如 `260-195` 与下一行 `=65` 都保留。
- 一个 unit 已完整写出“输入 + 运算 + 结果”时，后面只重复结果的 unit 不纳入。
- 错误算式及沿错误结果继续计算的步骤仍属于候选实际主线，要纳入；不要改成正确解法。
- 题面本来给出的数字/事实如果只是原样复述，且后面的入选算式已直接写出它，不纳入。
- 不纳入标题、计划话术、未代入的通用公式、未被最终结论使用的旁枝、验算性重复、重复等式、同义复述和 final wrapper。
- 不能把较早推导出的中间量当成“已知”直接删掉，也不能用你自己的更短公式替换候选实际做过的多步计算。

最后检查：`Key ⊆ Complete`，索引升序、无重复，并且只选择输入中 `kind="material_claim"` 的 unit。

## 4. 定标例子

### 最早错误优先于后续结果

- unit 0：`9×4=35`
- unit 1：`35+2=37`
- unit 2：`所以答案是37`

逐单元验算得 `9×4=36`，所以应标 `Key=[0]`、`Complete=[0,1]`。unit 1 只是沿用早先错误。

### 拆开的计算全部保留

- unit 0：`先列式 3×4`
- unit 1：`算得 12`
- unit 2：`再列式 12+2`
- unit 3：`算得 14`
- unit 4：`所以答案是14`

没有错误。应标 `Key=[3]`、`Complete=[0,1,2,3]`；unit 4 只是包装。

### 题面复述不进入 Complete

题目已给“上午卖 9 支、下午卖 6 支、退回 2 支”。

- unit 0：`9+6=15`
- unit 1：`题目说退回2支`
- unit 2：`15-2=13`
- unit 3：`答案13`

应标 `Key=[2]`、`Complete=[0,2]`。unit 1 是题面复述，unit 2 已写出数字 2。

## 5. 输出格式

每个输入行恰好输出一个单行 JSON，顺序可以跟输入一致。不要 Markdown、代码围栏、解释段落、额外字段或漏行：

```json
{"item_id":"原样复制","eligibility":"usable","key_unit_indices":[0],"complete_unit_indices":[0,1],"confidence":"high","rationale":"逐单元验算后，unit 0 的 9×4 应为36而不是35；unit 1只是沿用该错误"}
```

不可用行：

```json
{"item_id":"原样复制","eligibility":"no_auditable_reasoning","key_unit_indices":[],"complete_unit_indices":[],"confidence":"high","rationale":"只有答案，没有可审计推理"}
```

`confidence` 只能是 `high|medium|low`。`low` 只用于按上述算法仍确实无法稳定判断的行，不要把普通难题一律标 low。
